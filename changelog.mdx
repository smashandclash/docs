<Update label="October 2026" description="Smash&Clash for Minecraft">
  - **[Smash&Clash for Minecraft](https://github.com/smashandclash/minecraft)**, a new open-source SDK example: a table in a Minecraft world, for Java Edition 26.3 (Fabric) and Bedrock Edition (an add-on for Bedrock Dedicated Server). The board, cards and deck are in the world for everyone nearby to see, your hand is in your inventory, and the website's animations play on the board. House games, quick match and room codes, on the same network as every other client.
  - Its seats play as `minecraft` and `minecraft-bedrock` in `clients`.
</Update>

<Update label="October 2026" description="Smash&Clash 2.1.0: every client, in the apps too">
  - **The apps join the network.** Smash&Clash 2.1.0 for Android, Windows, macOS and Linux carries [one game, every client](/clients) to the installed apps: their room codes and quick match are the same as smashandclash.in's, the CLI's, Telegram's and every SDK app's. Android is on Google Play (internal testing first); every installer is on [smashandclash/installers](https://github.com/smashandclash/installers/releases/latest), with the steps in [Install the apps](/apps).
  - **Telegram** ([tg.smashandclash.in](https://tg.smashandclash.in)): **Play a friend** makes a room code anyone joins on any client, and **Join** takes a code or link from any of them.
  - **tldraw** ([smashandclash/tldraw](https://github.com/smashandclash/tldraw)): the board gets **Room code** and **Join a game**, on SDK 0.5.0.
  - **Glasses** (smashandclash.in/glasses): rooms and quick match on the network too.
  - Every game names the client each seat plays from in `clients`: `smashandclash.in`, `android`, `windows`, `discord`, `whop`, `glasses`, `smashandclash-cli`, `smashandclash-telegram`, `tldraw`, `smashandclash-ds`, `smashandclash-psp`, `mcp`, or an SDK app's `client` name.
  - Agent Plugin 2.4: the skills know every client shares codes, links and the quick-match queue.
</Update>

<Update label="October 2026" description="One game, every client: SDK and CLI 0.5.0">
  - **[One game, every client](/clients).** Every client meets on one game network. **Play a friend** on smashandclash.in now makes a room on the network: its code is joined from the website, its apps, the CLI, any SDK app or an agent over MCP, and their codes go in the website's **Join** box. Quick match on the website waits in the same queue as SDK apps and agents.
  - `sc.games.open(anything)`: a code or join link (a seat; a full room opens to watch), an invite (Telegram's `t.me` links too), a watch link, a replay or a challenge. `parseLink()`, `joinLink()`, `watchLink()`, `game.joinLink`, `game.watchLink`, `sc.games.byCode(code)`.
  - `game.leave()` leaves a room nobody joined, or the queue, and never resigns a game that started a moment before (`POST /games/{id}/resign` with `ifWaiting`).
  - `rating` on `createDuel`, `joinDuel`, `quickMatch` and `claim`, and `ratings` on games: a game between two rated people is rated on both sides. `clients` on games: the client each seat plays from.
  - CLI: `smashandclash open <code | link>`; `duel create` prints the join link. MCP: `join_duel` takes a join link too. REST: `GET /games/code/{code}`; `GET /games/{id}/wait` now returns when the game starts.
</Update>

<Update label="October 2026" description="SDK and CLI 0.4.1: steadier on a bad connection">
  - A dropped connection no longer ends the call. Reads are tried again, and so is any call whose connection never opened.
  - A move or a resignation is sent again only if the game shows it didn't land, so nothing is played twice. Calls that make something (a game, a duel, a challenge) aren't sent twice.
  - New: `isNetworkError(e)`. The CLI reports every dropped connection as `NETWORK` (exit 5).
</Update>

<Update label="October 2026" description="SDK and CLI 0.4.0: watch any game live">
  - **[Watch pages](/play/watch).** Every game has one: `https://www.smashandclash.in/watch/<game id>` plays it as it happens on the real board, with the game's animation, music and voices. Hands stay face-down. Games carry it as `watchPage`.
  - **Smash&Clash TV.** [`/tv`](https://www.smashandclash.in/tv) shows the game being played now and moves on to the next.
  - **On a stream.** `?overlay=1` for a clean browser source, `?delay=30` for a stream delay, `?mute=1`.
  - **Moves as data, for spectators.** `GET /games/{id}/sync` without a token is a spectator's sync: every move with its public events and the board after it, both hands as counts, `lastMoveAt` for a turn clock. `GET /games/featured` is the game to stream now.
  - `@smashandclash/sdk` and `smashandclash` **0.4.0**: `sc.games.feed(id)`, `watchSync(id)`, `featured()`; CLI `watch` prints each move as it lands, and `tv` follows the game being played now.
</Update>

<Update label="October 2026" description="Card #44 is Lizzie Jr.">

<Update label="October 2026" description="Design system: smashandclash.design">
  - **[`smashandclash.design`](/build/design)**: Smash&Clash's look as a [.design](https://github.com/AgentsORG/DESIGN) file, so agents build clients that feel like Smash&Clash. Colours, type, shapes, motion, sound, components, voice and rules; the game's high-contrast mode as a theme. The same tokens ship as CSS variables: [`smashandclash.tokens.css`](https://www.smashandclash.in/smashandclash.tokens.css).
  - **Your own flavour.** Extend the file and override what `policy.flavor` allows: the world, candies, faces, corners, tilt, motion. Card colours, you / them colours and the access rules stay.
  - We recommend the [design-engineering](https://github.com/AgentsORG/design-engineering) skill for any client: `npx skills add AgentsORG/design-engineering`.
</Update>

<Update label="October 2026" description="Agent Plugin 2.2">

  - The SDK, CLI, play and WebMCP skills know 0.3.0: the asset kit, profiles and leaderboards, card ids and moves as data.

<Update label="October 2026" description="SDK and CLI 0.3.0: build your own client">
  - **Card art and animation.** [`/games/cards`](/reference/cards) now gives each character its frameless art, its colour as hex, its VS poses and its attack drawings, with the pivot and scale to draw them. See [Cards and art](/build/art) and [Attack animation](/build/animation).
  - **The kit.** `/games/assets` (`sc.assets()`) lists the logo, fonts, card back and template, value-badge colours, every frame colour, attack timing, music, sound effects, the announcer and every character's voice lines. See [Build your own client](/build/overview) and [Sound](/build/sound).
  - **Players and leaderboards.** Public profiles (`/players/{id}`) and club, Discord and Whop leaderboards (`/leaderboards/{id}`, `/clubs/{code}`). See [Players and leaderboards](/players).
  - **The game view, for clients.** Every card in a view carries its `cardId`, and on your turn `view.moves` lists the legal moves as data. MCP tools leave it out.
  - `@smashandclash/sdk` and `smashandclash` **0.3.0**: `sc.assets()`, `sc.players.get()`, `sc.clubs.get()`, `sc.leaderboards.get()`, `cellToRC`, `rcToCell`, `boardSides`; CLI `assets`, `player`, `club`, `leaderboard`.
  - **Using the art.** The art, audio and characters are free to use in clients and apps built for Smash&Clash. They stay Smash&Clash's: never present them as your own.
</Update>

<Update label="October 2026" description="Example: Tournament Organizer">
  - **New example: [Tournament Organizer](https://github.com/smashandclash/tournament-organizer).** An open-source $SMASH tournament platform built on the SDK: entries paid per match into a pool, fair pairing, matches played in the app on [hosted matches](/play/hosted-matches), and the most wins takes the pool, paid out on Solana (devnet by default). It also covers practice, live games, replays and reviews, the deck and rules, and AI agent challenges, and ships five example looks. See [Examples](/sdk#examples).
  - **Developer terms.** [Section 14A of the Terms](https://www.smashandclash.in/terms#developers) covers building on the API and the SDK: paid tournaments use $SMASH only, state their age rule, and are their organisers' sole responsibility.
</Update>

<Update label="October 2026" description="SDK and CLI 0.2.1">
  - **The SDK works in browsers as is.** `@smashandclash/sdk` **0.2.1** calls the browser's `fetch` correctly (0.2.0 threw "Illegal invocation" in a browser unless you passed your own), and the API now allows the `X-SDK` header the SDK sends cross-origin. On 0.2.0 in a browser? Upgrade, or see [In a browser](/sdk#in-a-browser).
  - `smashandclash` **0.2.1** follows the SDK; nothing else changed (`npx smashandclash@latest`).
  - **New example: [Smash&Clash on a tldraw board](https://github.com/smashandclash/tldraw).** A complete client built on the SDK, plus a minimal board and five Node scripts. See [Examples](/sdk#examples).

<Update label="October 2026" description="People play too">
  - **Agents play people.** `create_duel` with `opponent: "person"` returns an invite link. The person plays it in the real game in their browser (or the CLI) while your agent plays its seat. See [Play a person](/play/people).
  - **People play people.** Host a match between two people with two invite links: `create_match`, `mode: "match"`. See [Host a match](/play/hosted-matches).
  - **Quick match.** The online queue pairs whoever is waiting, agent or person, as each agrees: `find_match`, `mode: "quick"`.
  - **Watch, replays and reviews.** Public listings (`/games/live`), a spectator's wait, and finished games as data: `/games/{id}/replay`, `/games/{id}/review`, and any shared replay link.
  - **Draw your own board.** `/games/{id}/sync` returns your seat's state and every move's public events.
  - **The deck as data:** `/games/cards`.
  - **Fair play, written down.** A seat never sees a hidden card, and the seed shows only once a game is over. See [Fair play](/reference/fair-play).
  - `@smashandclash/sdk` and `smashandclash` **0.2.0** on npm (`npm install @smashandclash/sdk@latest`, `npx smashandclash@latest`). Games now carry `playerKinds`, and a waiting game carries `openSeats`.
</Update>

<Update label="October 2026" description="Agents play">
  - **Agents play Smash&Clash themselves.** They play the house opponent (800–1600 ELO) or each other in duels, over MCP (`start_game`, `create_duel`, `join_duel`, `play_move`, `wait_for_turn`, …) and REST (`/api/v1/games`).
  - **Challenges are now Hosted Agent Challenges, powered by AgentsORG:** an agent hosted on Smash&Clash plays the human on your behalf.
  - **New:** `@smashandclash/sdk` (beta), the `smashandclash` CLI (beta), WebMCP tools on the game page, six agent skills (`npx skills add smashandclash/plugin`), and a Claude Code mod.
  - **The API is versioned** (`/api/v1`, `API-Version: 1`), and every response carries IETF rate-limit fields.
</Update>
